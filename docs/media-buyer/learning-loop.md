# لوب التعلّم

1. **يقرأ:** كل تحليل يقرأ `ads` و`ad_metrics` (قراءة بس) ويطلع توصيات (`recommend`).
2. **يمر على المدقق:** حكم التسويق يمنع التوصية اللي تعارضه، واللي منعه يظهر مع السبب.
3. **ينقاس:** لكل توصية نفّذها المشتري الإعلامي، نقارن الحملة بعد 3 و7 أيام بما قبل التنفيذ (`judgeOutcome` في `learn.ts`): نجحت، ما تغيّر، أسوأ، أو غير واضح (عينة صغيرة). التوصية اللي ما انفّذت ما تدخل في الحساب.
4. **يتعلّم:** `tune` يجمع النتائج لكل قاعدة. ولما يتجمع 8 نتائج واضحة أو أكثر، وإذا نجح أقل من 40% يقترح تشديد العتبة، وإذا نجح 80% بدون ولا نتيجة أسوأ يقترح تخفيفها.
5. **يرفع PR تطويري:** أي اقتراح على الإيجنت نفسه (عتبة، قاعدة جديدة، مصدر جديد) يرجع كـ PR باسم `buyer/<موضوع>` يغيّر ملفات `src/modules/buyer/` و`docs/media-buyer/` فقط، بالقالب `.github/PULL_REQUEST_TEMPLATE/buyer-improvement.md`: وش تغيّر، الدليل (أعداد بدون أرقام أعمال)، نتيجة الاختبارات. المدير يجمع المقترحات في ملخص، ولين تدمج. **ما ينصب أي تغيير تلقائياً.**

## قيود اللوب
- ما يكتب أرقام أعمال ولا أسماء حملات في السجلات ولا في الـ PR (أعداد وأسماء قواعد بس).
- حفظ نتيجة كل توصية (جدول) **مو مبني بعد**: المرحلة الجاية. حالياً `learn.ts` يشتغل على نتائج تُمرَّر له.
- بيانات الاختبار صناعية.
