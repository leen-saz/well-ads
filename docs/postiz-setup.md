# تشغيل Postiz خطوة بخطوة (تيك توك وX ولينكدإن)

هالدليل لك أنتِ، بدون خبرة تقنية. كل أمر تنسخينه وتلصقينه كما هو. كل مفتاح أو كلمة سر تكتبينها **أنتِ بنفسك** (ما نطلبها، ولا نكتبها في GitHub ولا في المحادثات). الملفات الجاهزة في `deploy/postiz/` والشرح التقني للمطوّر في `docs/social-engine.md`.

## قبل ما تبدئين: الصورة كاملة

| | الوقت المتوقع | ملاحظة |
|---|---|---|
| السيرفر والدومين والتشغيل (الأقسام 1 إلى 3) | نصف يوم تقريباً | هذا الجزء كله بيدك وما يحتاج موافقة أحد |
| تسجيل التطبيقات عند المنصات (القسم 4) | ساعة لكل منصة | ثم ينتظر **موافقة المنصة، وهذا اللي ياخذ أسابيع** |
| ربط الحسابات وأول منشور (الأقسام 5 و6) | ساعة | بعد ما توافق المنصات |

**نصيحتي: سوّي القسمين 1 و2 اليوم (يطلعون لك العنوان)، وقدّمي طلبات المنصات (القسم 4) في نفس اليوم**، لأن الانتظار عندهم هو أطول شي. الطلبات تحتاج الدومين الفرعي شغّال على HTTPS (تيك توك يتحقق منه)، فخلّصي القسم 3 أول، وبعدها قدّمي الطلبات وانتظري وإنتِ تكملين الباقي.

**وش المتوقع بصراحة:**
- فيسبوك وانستقرام ما يمرون على Postiz. يشتغلون من ربط Meta الموجود عندنا.
- **تيك توك**: بعد موافقة التطبيق، المنشورات تطلع **خاصة (للحساب نفسه فقط)** لين يعدّي تطبيقنا «التدقيق» (audit) عند تيك توك. هذا حد من تيك توك مو من عندنا. التدقيق ما له وقت معلن من تيك توك، والمصادر اللي لقيناها تقول من أسبوعين إلى ستة أسابيع تقريباً.
- **X**: الباقة المجانية للنشر بالـAPI **أُغلقت على المطوّرين الجدد** (فبراير 2026 حسب مصادر خارجية). الآن الدفع حسب الاستخدام برصيد تشترينه. راجعي السعر في لوحة X قبل لا تشترين (القسم 4).
- **لينكدإن**: Postiz يطلب صلاحيات الصفحات حتى لو بتنشرين من حسابك الشخصي، فالربط **يحتاج موافقة لينكدإن** (أيام إلى أسابيع) قبل أي منشور.

## 1) استئجار سيرفر صغير

### وش نوصي به
**Hetzner Cloud، الجهاز `CX33` (4 معالجات، 8 جيجا رام، 80 جيجا تخزين)، نظام Ubuntu 24.04.**
- التكلفة المتوقعة: من **7 إلى 10 يورو بالشهر** (حوالي 30 إلى 40 ريال)، تقريباً. الأسعار عند Hetzner تغيّرت أكثر من مرة في 2026 والمصادر ما تتفق، فالرقم الصحيح يظهر لك في صفحة الطلب قبل ما تدفعين.
- 4 جيجا رام هو الحد الأدنى (Postiz مع Temporal وElasticsearch ثقيل شوي). لا تختارين أقل. 8 جيجا أريح وما يفرق كثير بالسعر.
- المنطقة: Hetzner ما عنده سيرفرات في السعودية. اختاري **ألمانيا (Falkenstein أو Nuremberg) أو فنلندا (Helsinki)**. البعد ما يضر هنا: السيرفر يكلّم المنصات، وفريقك يفتح لوحة وحدة بس.
- إذا ما توفر الجهاز عند الطلب (Hetzner نشر تنبيه «توفر محدود» في يونيو 2026): بديل مناسب **DigitalOcean، منطقة Frankfurt، جهاز 4 جيجا رام** بحوالي 24 دولار بالشهر.

### وش تضغطين
1. افتحي `console.hetzner.cloud` وسوّي حساب. ممكن يطلبون تحقق هوية أو بطاقة، هذا طبيعي.
2. **New project** وسمّيه `well`.
3. **Add Server** واختاري:
   - Location: Falkenstein (أو Nuremberg أو Helsinki)
   - Image: **Ubuntu 24.04**
   - Type: **Shared vCPU ← Cost-optimized ← CX33**. إذا ما لقيتيه خذي أقرب جهاز **4 vCPU / 8 GB** أو **2 vCPU / 4 GB** على الأقل.
   - Networking: خلي **Public IPv4** مفعّل.
   - SSH keys: اضغطي **Add SSH key**. على جهازك (Terminal) شغّلي `ssh-keygen -t ed25519` ودوسي Enter على كل سؤال، ثم `cat ~/.ssh/id_ed25519.pub` وانسخي السطر كامل والصقيه هناك. (هذا الملف العام، آمن تلصقينه. لا ترسلين الملف الثاني اللي بدون `.pub` لأحد.)
   - Backups: فعّليها (تزيد 20% تقريباً). هي نسخة ثانية فوق نسخنا الليلي.
   - Name: `postiz`
4. **Firewall** (من القائمة اليسار) ← Create Firewall ← Inbound rules: **TCP 22** (SSH)، **TCP 80**، **TCP 443**، ولا شي غيرها. طبّقيه على السيرفر `postiz`. (الملفات عندنا أصلاً ما تفتح غير 80 و443، وهذا حاجز ثاني.)
5. بعد دقيقة يطلع لك **عنوان IP** للسيرفر. انسخيه، تحتاجينه في القسم 2.

### جهّزي السيرفر (مرة وحدة)
من Terminal في جهازك (بدّلي `IP` بعنوان السيرفر):
```bash
ssh root@IP
```
أول مرة يسأل «Are you sure…» اكتبي `yes`. بعدين الصقي هذي السطور وحدة وحدة:
```bash
apt-get update && apt-get -y upgrade
curl -fsSL https://get.docker.com | sh
apt-get install -y git age rclone
git clone --depth 1 https://github.com/leen-saz/well-ads /opt/well-ads
cp -r /opt/well-ads/deploy/postiz /opt/postiz
```
(السطر الثاني هو التثبيت الرسمي لـDocker من docker.com.) إذا طلع لك بعد `upgrade` طلب إعادة تشغيل، اكتبي `reboot` ثم ادخلي مرة ثانية بنفس أمر `ssh`.

## 2) ربط عنوان فرعي بالسيرفر (مثلاً `social.دومينك.com`)

1. ادخلي على المكان اللي فيه DNS لدومينك (غالباً Cloudflare ← الدومين ← DNS ← Records).
2. **Add record**: النوع **A**، الاسم `social`، العنوان = IP السيرفر.
3. في Cloudflare: **Proxy status = DNS only (السحابة الرمادية)**، مو البرتقالية. السبب: شهادة HTTPS تجي من Caddy مباشرة، وتيك توك لازم يوصل لملفات الوسائط على العنوان نفسه.
4. تأكدي بعد دقيقتين من Terminal جهازك:
   ```bash
   dig +short social.دومينك.com
   ```
   لازم يطلع عنوان IP السيرفر. إذا فاضي، انتظري شوي وأعيدي. **لا تكملين للقسم 3 قبل ما يطلع.** (اكتبي الدومين بالإنجليزي، مثل `social.example.com`.)

## 3) تشغيل Postiz وإنشاء أول مستخدم وإغلاق التسجيل

على السيرفر (`ssh root@IP`):

1. جهّزي ملف الإعدادات:
   ```bash
   cd /opt/postiz
   cp .env.example .env
   chmod 600 .env
   nano .env
   ```
2. عدّلي هالأسطر (اكتبي دومينك الحقيقي وإيميلك):
   - `POSTIZ_DOMAIN=social.example.com` (بدون https وبدون `/`)
   - `ACME_EMAIL=` إيميلك (Let's Encrypt يراسلك لو الشهادة قاربت تنتهي)
   - `JWT_SECRET` و`POSTIZ_DB_PASSWORD` و`TEMPORAL_DB_PASSWORD`: لكل واحد طلّعي قيمة عشوائية بهذا الأمر (في نافذة ثانية أو قبل `nano`) والصقيها مكان `CHANGE_ME…`:
     ```bash
     openssl rand -hex 32
     ```
     (استخدمي قيمة مختلفة لكل واحد. خزّنيها في مدير كلمات السر.)
   - اتركي `DISABLE_REGISTRATION=false` لحد ما تسوين أول مستخدم.
   - حفظ في nano: `Ctrl+O` ثم Enter ثم `Ctrl+X`.
3. شغّلي:
   ```bash
   docker compose up -d
   ```
   أول مرة ينزّل صور كثيرة ويأخذ 5 إلى 10 دقائق. بعدها انتظري 3 دقائق ثم:
   ```bash
   docker compose ps
   ```
   كل الخدمات لازم تكون `running` أو `healthy`. إذا وحدة واقفة: `docker compose logs --tail 80 اسم_الخدمة` وصوّري لنا الخطأ (بدون ما يظهر فيه أي مفتاح).
4. افتحي `https://social.دومينك.com` في المتصفح. لازم يظهر قفل HTTPS وصفحة تسجيل. **سجّلي أنتِ أول مستخدم** (إيميلك وكلمة سر قوية فريدة، واسم الشركة Well).
5. **فوراً بعدها** اقفلي التسجيل حتى ما أحد يقدر يسوي حساب:
   ```bash
   cd /opt/postiz
   sed -i 's/^DISABLE_REGISTRATION=.*/DISABLE_REGISTRATION=true/' .env
   docker compose up -d
   ```
   تأكدي: افتحي الرابط في نافذة خاصة (Private). ما لازم تقدرين تسجّلين حساب جديد. (توثيق Postiz يقول إن هذا الإعداد يعطّل أيضاً الدخول بـOIDC، ونحن ما نستخدمه.)
6. تأكدي إن المنافذ الداخلية مقفلة، من Terminal **جهازك** (بدّلي IP):
   ```bash
   nc -zv -w 3 IP 5432; nc -zv -w 3 IP 6379; nc -zv -w 3 IP 7233; nc -zv -w 3 IP 8080
   ```
   كلها لازم تفشل (timed out أو refused). إذا واحد منها «succeeded» أوقفي كل شي وكلمينا.

### النسخ الاحتياطي (لازم قبل ما تربطين أي حساب)
لو ضاع السيرفر أو انحذفت قاعدة البيانات، كل الحسابات تنربط من جديد. فنسوي النسخ الليلي الآن:

1. **على جهازك** (مو السيرفر)، سوّي مفتاح التشفير:
   ```bash
   brew install age
   age-keygen -o ~/postiz-backup-key.txt
   ```
   يطبع سطر يبدأ بـ`Public key: age1…`. هذا **العام**. الملف `postiz-backup-key.txt` هو **الخاص**: انسخيه لمدير كلمات السر ولمكان ثاني (فلاش أو iCloud). بدونه ما تفتحين أي نسخة احتياطية، وما نقدر نساعدك نرجّعه.
2. على السيرفر: `nano /opt/postiz/.env` وحطي المفتاح العام في `BACKUP_AGE_RECIPIENT=age1…`.
3. مكان خارج السيرفر للنسخ. الأسهل عندك: **Cloudflare R2** (يعطيك 10 جيجا مجاناً):
   - Cloudflare ← R2 ← Create bucket، الاسم `well-postiz-backups`.
   - R2 ← Manage API tokens ← Create token بصلاحية **Object Read & Write** للـbucket هذا فقط. تطلع لك قيمتين (Access Key ID وSecret) تظهر مرة وحدة: خزّنيها.
   - على السيرفر: `rclone config` ثم `n` (new) والاسم `r2`، نوع التخزين `s3`، المزوّد `Cloudflare`، والصقي القيمتين بنفسك، وفي Endpoint اكتبي `https://رقم_الحساب.r2.cloudflarestorage.com` (رقم حساب Cloudflare يظهر في صفحة R2)، وباقي الأسئلة Enter.
   - في `.env`: `BACKUP_RCLONE_REMOTE=r2:well-postiz-backups`
4. شغّلي أول نسخة يدوياً:
   ```bash
   cd /opt/postiz && ./backup/backup.sh
   ```
   لازم تنتهي بـ`done, copied to the off-site remote`. إذا طلع `no off-site copy` فالنسخة ما طلعت خارج السيرفر وما تحسب.
5. فعّلي التشغيل كل ليلة (الساعة 5:30 صباحاً بتوقيت الرياض):
   ```bash
   cp /opt/postiz/backup/postiz-backup.cron /etc/cron.d/postiz-backup
   ```
   اختياري ومفيد: سوّي مراقب مجاني في healthchecks.io وحطي رابطه في `BACKUP_PING_URL`، يرسل لك إيميل إذا وقفت النسخ.
6. **اختبار الاستعادة**: افتحي `deploy/postiz/RESTORE-TEST.md` وسوّي القائمة على سيرفر مؤقت. هذا اللي يثبت إن النسخة تنفع. سوّيه مرة الآن (قبل ربط الحسابات، عشان وقتها ما في شي تخسرينه) ومرة بعد كل ترقية.

## 4) تسجيل تطبيقات المطوّرين (التطبيق يتسجّل عند كل منصة)

**القاعدة العامة:** عنوان الرجوع (Redirect URI) يكون دايماً:
`https://social.دومينك.com/integrations/social/اسم_المنصة`

| المنصة | عنوان الرجوع الدقيق | مفاتيح `.env` |
|---|---|---|
| تيك توك | `https://social.دومينك.com/integrations/social/tiktok` | `TIKTOK_CLIENT_ID`, `TIKTOK_CLIENT_SECRET` |
| X | `https://social.دومينك.com/integrations/social/x` | `X_API_KEY`, `X_API_SECRET` |
| لينكدإن (حساب شخصي) | `https://social.دومينك.com/integrations/social/linkedin` | `LINKEDIN_CLIENT_ID`, `LINKEDIN_CLIENT_SECRET` |
| لينكدإن (صفحة شركة) | `https://social.دومينك.com/integrations/social/linkedin-page` | نفس مفاتيح لينكدإن (تطبيق واحد) |

(هذي مأخوذة من صفحات Postiz الرسمية لكل مزوّد. إذا اختلف شي عندك على الشاشة، الشاشة هي الصح، وقولي لنا.)

بعد ما تنسخين مفاتيح أي منصة: `nano /opt/postiz/.env` والصقيها، ثم **`docker compose up -d`** (مو `restart`، لأنه ما يقرأ `.env` من جديد). المفاتيح تنكتب في `.env` على السيرفر فقط.

### أ) Meta (فيسبوك وانستقرام): مو عبر Postiz
النشر فيهم من كودنا مباشرة عبر ربط Meta في صفحة **Connectors ← Meta pages**. ما تحتاجين Postiz لهم ولا تعبين `FACEBOOK_*` في ملف Postiz.
- الصلاحيات اللي يطلبها ربط النشر عندنا: `pages_show_list` و`pages_read_engagement` و**`pages_manage_posts`** (نشر فيسبوك) و`instagram_basic` و**`instagram_content_publish`** (نشر انستقرام) و`business_management`.
- في تطبيق Meta (developers.facebook.com ← تطبيقك ← Facebook Login ← Settings) أضيفي في **Valid OAuth Redirect URIs** عنوان الرجوع اللي تشوفينه في بطاقة Meta داخل صفحة Connectors عندنا (يكون `https://عنوان-موقعنا/api/connectors/callback`).
- حساب انستقرام لازم يكون **Business أو Creator** ومربوط بصفحة الفيسبوك.
- الموافقة: لو التطبيق في وضع Development وأنتِ أو صاحب الصفحة عندكم دور في التطبيق، النشر لصفحاتكم يشتغل بدون مراجعة. للانتقال لوضع Live وصلاحيات Advanced (لأي صفحات غير صفحاتكم) تحتاجين **App Review** وغالباً توثيق النشاط التجاري عند Meta، وهذا ياخذ أيام إلى أسابيع. (هذا من معرفتنا بنظام Meta العام، مو مجرّب على تطبيقنا.)

### ب) تيك توك (TikTok for Developers)
1. افتحي `developers.tiktok.com/apps` ← Connect an app (Create app). الاسم مثلاً `Well Social`. اختاري منصة **Web**.
2. لازم **رابط شروط الاستخدام** و**سياسة الخصوصية** على صفحات عامة بـHTTPS (من موقع Well).
3. أضيفي المنتجين **Login Kit** و**Content Posting API**، وفعّلي في Content Posting API خيار **Direct Post**.
4. في Login Kit حطي عنوان الرجوع من الجدول فوق. (توثيق Postiz يذكر `localhost` لبيئة التطوير، لا تستخدمينه. استخدمي عنوانك الحقيقي، وتيك توك يرفض http.)
5. الصلاحيات (Scopes): `user.info.basic` و`video.create` و`video.publish` و`video.upload` و`user.info.profile`.
6. **تحقق الدومين**: تيك توك يسحب الصور والفيديو من عنوانك (`https://social.دومينك.com/uploads/...`) فلازم يكون العنوان مسجّل ومتحقق منه في التطبيق (URL properties). الأسهل التحقق بسجل **DNS TXT** يعطيك تيك توك قيمته. وإذا اخترتي التحقق بملف، في `Caddyfile` مثال جاهز معلّق (مو مجرّب عندنا).
7. انسخي `Client key` و`Client secret` (16 و32 خانة حسب توثيق Postiz) في `.env`.
8. قدّمي التطبيق للمراجعة (Submit for review). تيك توك عادةً يطلب شرح الاستخدام وفيديو يوضح الربط والنشر داخل منتجنا.
9. **المواعيد بصراحة:**
   - مراجعة التطبيق: تيك توك يقول «عدة أيام إلى أسبوعين» حسب ما نقلته مصادر.
   - **التدقيق (audit)** منفصل عن المراجعة. قبله، **أي منشور يتحول لخاص (SELF_ONLY)** مهما اخترنا، وبحد 5 مستخدمين في 24 ساعة وحساباتهم خاصة. المصادر الخارجية تقول 2 إلى 6 أسابيع.
   - يعني: **أول منشور ممكن يصير تجريبي خاص**، والعام ينتظر التدقيق. هذا مو عطل عندنا.

### ج) X (developer.x.com)
1. ادخلي `developer.x.com/en/portal/dashboard` وسوّي مشروع وتطبيق.
2. **السعر (مهم قبل لا تكملين):** الباقة المجانية للنشر **أُغلقت للمطوّرين الجدد** حسب مصادر خارجية (مطلع فبراير 2026)، والنموذج الحالي **شراء رصيد ودفع لكل عملية**. أرقام الحدود القديمة (500 أو 1500 منشور بالشهر) كلها قديمة ولا تعتمدين عليها. شوفي السعر لكل منشور داخل لوحة X نفسها، وحطي سقف صرف إن وُجد. توقعنا أن حجمنا (منشورات قليلة) تكلفته صغيرة، بس هذا نتأكد منه من اللوحة مو من كلامنا.
3. App settings ← **User authentication settings**:
   - App permissions: **Read and write**
   - Type of app: **Native App** (مهم: لو اخترتي Web App يفشل الربط بخطأ 32 حسب توثيق Postiz)
   - Callback URI: العنوان من الجدول.
   - Website URL: موقع Well.
4. تبويب **Keys and tokens** ← Consumer Keys ← Regenerate، وانسخي `API Key` و`API Key Secret` في `.env` (`X_API_KEY` و`X_API_SECRET`).
5. الموافقة: غالباً فورية عند الدفع، بدون مراجعة طويلة. الحد الفعلي هو الرصيد وحدود الطلبات اللي تظهر في اللوحة.

### د) لينكدإن (linkedin.com/developers)
1. **Create app**: يطلب صفحة لينكدإن (Company Page) ترتبط بالتطبيق، وشعار. اختاري صفحة Well.
2. تبويب **Products** وأضيفي:
   - **Share on LinkedIn** (يتفعل غالباً فوراً)
   - **Sign In with LinkedIn using OpenID Connect** (فوراً)
   - **Advertising API**: يحتاج **تعبئة نموذج طلب وموافقة لينكدإن**. توثيق Postiz يقول بدونه ما تتجدد التوكنات.
3. تبويب **Auth ← OAuth 2.0 scopes** لازم تشوفين كل هذي: `openid` و`profile` و`w_member_social` و`r_basicprofile` و`rw_organization_admin` و`w_organization_social` و`r_organization_social`. إذا ناقص واحد، لينكدإن **ما يفشل** بس يعطي توكن ناقص، وPostiz يرفض الربط بخطأ `NotEnoughScopes`. هذا أكثر خطأ متوقع.
4. **مهم:** توثيق Postiz يقول إن صلاحيات المنظمة (الأربعة الأخيرة) مطلوبة **حتى لو ربطتي حساب شخصي**. يعني ما تقدرين تبدين بحسابك الشخصي بسرعة وتنتظرين الصفحة بعدين: الاثنين يحتاجون الموافقة.
5. إذا لينكدإن سمّى المنتج الذي يعطي صلاحيات الصفحات باسم **Community Management API** (كما في `docs/social-engine.md`) بدل Advertising API، قدّمي طلبه. المهم النتيجة: أن تظهر الصلاحيات السبع في Auth. (التسمية عند لينكدإن تتغير، وما قدرنا نجرّب.)
6. أضيفي عنواني الرجوع (`linkedin` و`linkedin-page`) في **Auth ← Authorized redirect URLs**.
7. انسخي `Client ID` و`Client Secret` من Auth في `.env`.
8. الموافقة: من **أيام إلى أسابيع**، وقد يطلبون توثيق التطبيق من مسؤول الصفحة (Verify app). إذا رفضوا أو طلبوا معلومات، ردّي عليهم بوصف الاستخدام: «نشر محتوى صفحة Well بعد اعتماد داخلي».

---

## 5) ربط الحسابات داخل Postiz، ثم إنشاء المفتاح وتسجيله في Cloudflare

1. افتحي `https://social.دومينك.com` وادخلي. **Add Channel**، واختاري المنصة، وسجّلي دخول بحساب الشركة وامنحي الصلاحيات.
2. اربطي **حساب واحد فقط لكل منصة** (نظامنا يرفض يخمّن بين حسابين لنفس المنصة، ويقول لك على تبويب السوشال). لينكدإن: لو ربطتي حساب شخصي وصفحة، نستخدم الصفحة.
3. تيك توك: الصفحة قد تعلّق عند الربط (مشكلة معروفة في Postiz). جرّبي نافذة خاصة جديدة.
4. المفتاح: **Settings ← Developers ← Public API** (في بعض الإصدارات القديمة اسمها Settings ← Public API)، اضغطي أيقونة العين وانسخيه. تقدرين تغيّرينه من نفس المكان، وتغييره يلغي القديم فوراً.
5. سجّلي القيمتين **بنفسك** كأسرار Worker:
   - في Cloudflare ← Workers ← `well-ads` ← Settings ← Variables and Secrets ← Add ← النوع **Secret**:
     - `POSTIZ_URL` = `https://social.دومينك.com` (هذا فقط، بدون `/api`، نحن نكمّل المسار بأنفسنا)
     - `POSTIZ_API_KEY` = المفتاح
   - احفظي وانشري (Deploy).
   - أو من جهازك: `npx wrangler secret put POSTIZ_URL --name well-ads` ثم `npx wrangler secret put POSTIZ_API_KEY --name well-ads` وتلصقين القيمة عند السؤال.
   - بديل: بطاقة **Postiz** في صفحة Connectors (تختبر الزوج قبل الحفظ).
   - **ما ترسلين المفتاح لأحد** (ولا لنا). لو انكشف: غيّريه من Postiz، وحطي الجديد.
6. في تبويب **السوشال** اضغطي **«افحص الخدمة والحسابات»**. لازم يقول: الخدمة تستجيب، المفتاح صحيح، والمنصات المربوطة. المنصة غير المربوطة تظهر «غير متاح الحين»، وهذا طبيعي قبل الموافقات.

## 6) قائمة أول منشور تجريبي (من تبويب السوشال، بعد الاعتماد)

سوّيه لكل منصة على **حساب تجريبي** (أو حساب Well وأنتِ جاهزة تحذفين المنشور):
- [ ] «افحص الخدمة والحسابات» أخضر للمنصة اللي بنجرّبها.
- [ ] اكتبي منشوراً قصيراً **واضحاً إنه تجربة**، وحطي صورة صغيرة (فيديو MP4 لتيك توك). تيك توك لازم فيه وسائط.
- [ ] **قبل الاعتماد**: تأكدي إن المنشور ما طلع في الحساب ولا في Postiz (ما يصير أي نشر قبل اعتماد المعتمِد، هذا شرط عندنا).
- [ ] اعتمدي المنشور بحساب المعتمِد. انتظري دورة الجدولة (كل 5 دقائق).
- [ ] تأكدي إن حالة المنصة صارت «تمّ» وتطلع النتيجة في المنشور، وافتحي الحساب نفسه وتحققي إن المنشور موجود وبنفس النص والوسائط.
- [ ] تيك توك قبل التدقيق: المنشور يظهر **خاص** في حسابك فقط. هذا متوقع.
- [ ] لا تكررين الضغط إذا تأخر. إذا ظهرت حالة «غير مؤكد» (unconfirmed) فهذا معناه ما قدرنا نتأكد، وتشوفين الحساب بنفسك قبل أي إعادة (نظامنا ما يعيد الإرسال لوحده عشان ما يتكرر المنشور).
- [ ] احذفي المنشور التجريبي من المنصة.
- [ ] سجّلي لنا أي فرق عن المتوقع (الفرق بين الشاشة وهالدليل)، نحدّث الدليل.

## ما لم نختبره (بصراحة)
هذا الدليل والملفات كُتبت من توثيق Postiz الرسمي ومن الملف الرسمي لـdocker compose، **بدون سيرفر حقيقي**:
- ما شغّلنا `docker compose up` ولا تأكدنا إن إصدار Postiz المثبّت (`v2.25.3`، الأحدث وقت الكتابة) يشتغل مع بقية الخدمات بالأرقام المثبتة. شغّلي ثم راجعي `docker compose ps`.
