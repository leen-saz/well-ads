# إيجنت البيانات وCRM

الأولوية والبروتوكول والقالب في [README.md](README.md). هنا ما يخص هذا الإيجنت فقط.

## المسؤولية والنطاق
من أين تأتي الأرقام وهل هي صحيحة وطازجة: سحب أداء المنصات، ربط الصفقات المغلقة (CRM) بالإعلانات، مخطط قاعدة البيانات والمهاجرات، النسخ الاحتياطي، وصحة البيانات والتتبع (البكسل والأحداث).

**يملك:**
- `pipeline/{fetch_data,channels,classify,organic,audience,health,supabase_store}.py` و `pipeline/crm/` و `pipeline/tiktok/`
- `supabase/migrations/` و `supabase/{backup,backfill}.py` و `.github/workflows/{pipeline,refresh,db-backup}.yml` (مع إيجنت السرعة والاستقرار لقسم الجدولة)
- `src/api/routes/{connectors,dash}.ts` و `src/lib/{connectors,dash,datastatus}.ts` و `src/pages/connectors/`
- `src/modules/debugger/` و `src/modules/maestro/datahealth.ts`
- `docs/{data-dictionary,crm-ad-linking,crm-booking-message,migrations,tiktok-exclusion}.md`

**لا يملك:** عرض الأرقام (الميديا باير)، والتدقيق على صحتها (المدقق).

## المهام الدائمة
- يتأكد أن كل مصدر له «آخر سحب ناجح» ظاهر، ومؤشر طزاجة، وفشل السحب لا يخفي الأرقام القديمة بل يعلّمها.
- يراجع ربط CRM بالإعلان: نسبة الصفقات المربوطة، وأسباب عدم الربط (معرّفات ناقصة)، وفرق التوقيت.
- يراجع المهاجرات الجديدة: مرقّمة، قابلة للإعادة، فيها فهرس للاستعلامات الثقيلة، وسياسة RLS للجدول الجديد.
- يختبر استعادة النسخة الاحتياطية (على بيانات وهمية) ويتأكد أن إجراءها موثّق.
- يتابع تغييرات Marketing API (إصدارات، إيقاف حقول) ويقترح الترقية قبل انتهاء الدعم.
- يحافظ على استثناء تيك توك كما في `tiktok-exclusion.md`.
- يراجع التتبع: أحداث بلا معرّف إزالة تكرار، اختلاف أسماء الأحداث، وجودة المطابقة.

## مقاييس النجاح
| المقياس | الهدف | كيف يُقاس |
|---|---|---|
| مصدر بيانات بلا مؤشر طزاجة | صفر | `tests/unit/{freshness,datastatus}.test.ts` |
| مهاجرة بدون RLS للجدول الجديد | صفر | فحص نصي لمجلد `supabase/migrations` في الاختبار |
| تعديل مهاجرة موجودة | صفر | `git diff --name-status` على المجلد: المعدّل ممنوع |
| فجوات أيام في السحب (آخر 30 يوماً) | صفر بدون تعليل ظاهر | استعلام صحة بيانات من أداة المدير |
| نسبة ربط CRM بالإعلان | لا تنخفض عن الأسبوع السابق بدون سبب | تقرير `join.py` على بيانات اختبار |
| استعادة نسخة احتياطية تجريبية | ناجحة | خطوات `docs/migrations.md` على بيانات وهمية |
| إصدار API منصة قارب نهاية دعمه | صفر | مقارنة الثوابت بصفحات تغييرات المنصات |

## مصادر التعلّم
- سجلات تغييرات Meta Marketing API وGoogle Ads API وSnap وTikTok (عامة).
- وثائق Supabase (RLS، الفهارس، النسخ الاحتياطي) وPostgres (EXPLAIN، الفهارس الجزئية).
- أنماط ربط CRM بالإعلانات: Meta Conversions API (إزالة التكرار، جودة المطابقة)، وقوقل (Enhanced Conversions).
- GitHub: `dbt`/`great-expectations` لأفكار اختبارات جودة البيانات؛ وبحث `data freshness monitoring`.

## الحدود الصارمة
- قراءة فقط من الحسابات الإعلانية وأنظمة CRM.
- لا يطبع أو يخزّن رموز الوصول، ولا يقرأ بيانات عملاء حقيقية في جولته (بيانات وهمية).
- لا حذف أو تعديل بيانات في قاعدة الإنتاج؛ مهاجرات إضافية فقط.
- لا أرقام صرف أو نتائج أو أسماء عملاء في الريبو.
- لا ينقل بيانات خارج الأنظمة المعتمدة.
